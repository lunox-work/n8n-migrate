# Evaluation bench

Runs each template through gates 1–8 (PLAN Phase 5): n8n 2.47.7 in Docker is the baseline, the migrated folder is run by the runner, and the comparer decides whether both made the same effects. A template stops at its first failed gate.

## Commands

```
node evals/bench/run.mjs [<id>...] [--split dev] [--limit n] [--variants normal,empty,malformed,hostile]
     [--repeats 3] [--model-mode replay|live] [--driver inprocess|claude] [--skill <id,...|all>]
     [--tag <name>] [--reuse-convert <tag>] [--record] [--n8n-check all|normal] [--no-n8n-check] [--diagnose]
node evals/bench/judge.mjs --calibrate <id>[,<id>] [--variant normal]
node evals/bench/summary.mjs [--tag <name>] [--json]
node evals/bench/summary.mjs --release <dev tag> <held tag> [--flips n] [--round n]
node evals/bench/tls.mjs [host...]          # CA and leaves (made on demand by the bench)
node evals/bench/validate.mjs               # fixtures (FIXTURES.md)
```

`--tag` names a bench run; re-running the same tag resumes from `.work/ledger/<tag>.json`. `held-out` never runs without explicit ids (EXCLUSIONS.md).

**Rolling held-out** (PLAN Phase 6). `splits.json` keeps the seeded `dev`/`heldOut` lists and adds `rounds` and `currentRound`: after a release point is scored, the held-out templates it scored join dev (`promoted`), and the next release point scores fresh ones. `rounds.mjs` gives the current round to `run.mjs` (no ids or `--split dev`: the round's dev templates with fixtures), `convert-coverage.mjs --split dev` and `summary.mjs`. Round 2: dev = 60 seeded + held-out 1–20 (50 with fixtures), held-out = held-out 21–40 (scored at release point 2). Round 3: dev = all 100 seeded templates (70 with fixtures); held-out = 20 fresh templates from outside the seeded split (`splits.json` `heldOutFresh`, which `rounds.mjs` resolves like the seeded lists): the Phase 5 `overflow` entries plus a top-up walk of the listing (`fetch.mjs --top-up`, same exclusion rules, EXCLUSIONS.md), drawn by `split.mjs --fresh` (seed 20261115, per wake-up stratum, the seeded held-out's strata halved). Their fixtures are written by a separate blind session before release point 3. `summary.mjs --release <dev tag> <held tag> [--flips n] [--round n]` prints the gap and the overfitting bound with n = the round's fixtured sizes.

## Contract

- **n8n side.** Every call goes to the mock: plain HTTP through the proxy, HTTPS through CONNECT terminated with a leaf the container trusts (`NODE_EXTRA_CA_CERTS`); a host no fixture route names gets a leaf the mock makes from the bench CA (P26, `mint-leaf.mjs`), so its requests are logged (`mintedLeaf`) and answered like any unrouted request instead of a refused connection the Claude side never sees, and `logVsFixture.noFixtureHosts` lists them. Model nodes reach the shim through `http://mock:8080/model/<tag>`. A read uses its `http` source; its `n8n` pin is used only without one, or after the node failed on it (`pin-fallback`). A poll trigger with `http` responses polls once instead of being pinned (binary data cannot be pinned). Sources per node are in each row's `stubs`.
- **Credentials.** Every referenced credential gets a dummy; a node that needs one and has none (stripped export) gets its node type's (`credentialsAttached` in the row). Ollama (non-chat), Qdrant and Supabase point at `http://mock:8080` (`via: direct`, matched by path); S3 at the shortest host of the S3 routes; OAuth2 types get a token that never expires; fixture `file` sources are copied into the container owned by n8n's user, so a workflow that writes the same path can overwrite it (P49: 2894); the n8n container's `N8N_RESTRICT_FILE_ACCESS_TO` allows `/home/node`, the directory of every absolute `file` path in the fixtures (P21) and the directory written before any expression in the path of each disk-write node (Write Binary File, Read/Write Files from Disk) a fixture lists in `writes` (P25: 1826's `/tmp`); `N8N_BLOCK_FILE_ACCESS_TO_N8N_FILES` keeps its default, so n8n's own folder stays closed.
- **Model types** (P18). `n8n-side.mjs` `SHIM_MODELS` is the one list of model node types the shim answers, from n8n 2.47.7's node and credential sources. By credential (base-URL field to `/model/<tag>`): Anthropic, OpenAI chat and completion, Gemini, Ollama chat and completion, OpenRouter, DeepSeek, xAI Grok, Moonshot, NVIDIA, MiniMax, Vercel AI Gateway, Alibaba Cloud, Lemonade chat and completion, Azure OpenAI (API key, classic endpoint, OpenAI family); root nodes the fixture lists as models: OpenAI v1.x and the legacy OpenAI node (text, chat), the Anthropic, Google Gemini, Ollama and Moonshot vendor nodes (text). By fixed host (the mock forwards the model path, tag `host:<host>`, one node per host): Groq, Mistral, Google Vertex (service account), Hugging Face inference (the hub's provider lookup is a bench route, the shim speaks hf-inference text generation), OpenAI v1.x image analysis, and LLM APIs over HTTP to `api.openai.com`, `api.anthropic.com` or `openrouter.ai`. On the Claude side an `http` step to a model host's model path that no route answers is a model call too (P43): it gets n8n's recorded reply for that node and call index in the API's format, and its request body is checked like a replayed model input (gate 4), in process and under the claude driver (whose host mock forwards it to a replay shim, a miss answered canned); neither side counts it as an effect. Not answered (`UNSHIMMED_MODELS`, with reasons): Cohere chat and completion, AWS Bedrock, Databricks, the Alibaba Cloud and MiniMax vendor nodes, OpenAI node v2 (Responses API), Azure with Entra ID or the Claude family. `validate.mjs` errors on a `models` entry the shim cannot answer, an agent or chain fed by such a model, and two nodes routed by one host.
- **Overlay `env`.** `{NAME: value}`, merged over all of `config/` and set on the n8n container (recreated when it lacks one), with `N8N_BLOCK_ENV_ACCESS_IN_NODE=false`. The runtime keeps `$env` blocked by design, so the overlay's `claude.overrides` carry the same values into the steps that read them.
- **Binary triggers and form pages.** Trigger items with `binary` (uploads) are dropped by a pin: a Form Trigger gets a real multipart submission to its production URL (`--via form`; a run that reaches a Form ending page stops in `waiting`, where n8n leaves it until a browser loads the page), any other trigger runs with `--via cli` (a Code node returns the items). A fixture with `trigger.formPages` (P20) also runs `--via form`: n8n answers the trigger with its form-waiting URL, and each page is submitted there once n8n waits for it (`n8n-execution-status` = `form-waiting`), by label or by position; the recording keeps `formPages` (each page's status, or why it was skipped). The Claude side has no form pages yet (forms that wait are out of scope v1). Pages are answered in list order, not matched to the waiting node: a page count that depends on a model reply (2878's clarity questions, at most 3) is listed at its maximum, and a spare entry goes to the next waiting page.
- **Child executions** (P20). Every n8n run awaits the executions it started (a sub-workflow call, `waitForSubWorkflow: false` included), found by `parentExecution.executionId` (and theirs in turn), before the mock log is read, so their requests are in the run's effects; the recording keeps their statuses (`children`).
- **Poll mode** (P22). A poll trigger with `http` responses polls once in n8n's manual mode (a REST run from the trigger); see FIXTURES.md for what each trigger asks in that mode.
- **Unrouted reads** (P19). With bench routes, a read no route matches gets 404 `{"error":"no fixture"}`, logged `read-default` (the twin of `write-default`), on the n8n side, the in-process host and the claude driver's host mock alike; `logVsFixture.unanswered` lists them. A response with `any: true` answers every path on its origin (an exact-path response wins over it). A request the real service always refuses gets the service's error before any route (P29, `serviceRefusal()`, logged `service: …`, on the mock, the claude driver's host mock and the in-process host alike): Gmail `messages.send` whose raw message names no address in `To`, `Cc` or `Bcc` gets 400 `Recipient address required`. The connector mocks (MCP mock, in-process host, unit-test host) refuse the connector twins the same way (P33, `limits.mjs` `connectorRefusal()`, logged invalid with `refusal: true`, no effect): Gmail `reply` with `to` given and empty and no `cc`/`bcc` address, `send_message` without any address and no `draftId`, `forward` without any address. The connector's own answer is not captured; the message is the API's, marked assumed.
- **Unusable fixture routes** (P48). `validate.mjs` errors on a route `url` that `new URL()` rejects (no client can send it; an odd URL belongs in the data, not in a route). Should one reach a run, `routesOf()` leaves it out and names it, and that variant's n8n run is a `fixture error` (not run, nothing saved): the canned n8n check reports it per variant, the normal variant fails gate 3, a robustness variant fails gate 5 and the hostile one gate 6, all in the `fixture` bucket, instead of the template crashing at gate 0.
- **Model replies.** The first n8n run of a template variant is live and recorded; later runs replay it. The Claude side gets n8n's reply for the same model node and call index (replay, the default for gates 4–7) and the bench checks that the Claude request asked the same question (gate 4 fails otherwise). For a replayed agent turn after a tool call (P15) the Claude side must have run each tool n8n's reply asked for (by name) without an error, unless n8n's own result was empty or an error (`field map: tool call not executed`); each value it fed back must equal n8n's tool message for that call (P17: the content text for OpenAI, Anthropic and Ollama, `functionResponse.response.result` for Gemini; n8n 2.47.7 sends a node tool's output as JSON of its items' json, always a list, so a list of one item equals that item and the shape is reported as `tools.shape`, not gated; JSON compared when both parse, else squashed text, run-time timestamps masked) (`field map: different tool result`); and those calls' reads, keyed as `compare()` keys reads, must equal n8n's reads between the two model requests (recordings keep each model call's mock-log `seq`) (`different tool result`); a tool n8n served from a pin, or a recording without `seq`, leaves the reads unchecked and says so (`tools.reads`). The claude driver's normal run gets the same model-input and tool-turn checks (P16): its replay hook keeps each replayed request and the time its answer was written (`replayLog`), and a turn's reads are the MCP mock's and host http mock's log lines between the previous agent turn's answer and this one's (`drivers.claude.modelChecks` counts them). Each replayed request's tool list is compared with n8n's for the same call (P28): tool names (case and punctuation folded, as n8n makes a tool name from a node name) and each input schema's shape (property names, types, required, nested properties and items; no schema = no parameters) must match (`field map: different tools offered`, after the model-input check, before the tool turns); tool and parameter descriptions are reported by kind (`drivers.toolDefs.descriptionKinds`: `reworded`, `missing`), not gated, since n8n writes some itself (an action label plus the node's name), except a converter artefact: n8n expression syntax (a leading `=`, `{{ … }}`, `$fromAI(`) in the Claude side's text that n8n's evaluated text lacks fails gate 4 as `expression translation: tool description not evaluated` (P34); n8n's output-parser tool `format_final_json_response` is not a tool on the Claude side (the runtime asks with `outputSchema`), and the shape of its `output` property must equal the request's `outputSchema` (`field map: different output schema`, P35). The hostile run's replayed requests (in process and under the claude driver) get the tool-list check too, in gate 6 (`hostile: different tools offered`, P35). A miss falls back to live and is marked. `--model-mode live` answers the Claude side live and sends model-written fields to the judge. A run that may call the model live checks memory once before it starts (25% free) and its model calls skip the per-call gate; a run interrupted on the model side (shim error, or a model node failing on a transport error) is never saved and the row reads `bench error: recording interrupted` (P12). A stand-in reply whose whole text is its own answer envelope (`{"type":"text","text":…}`) is unwrapped, again while it nests, cached draws included; a reply n8n rejects is never re-drawn (P13). A stand-in reply whose whole text is JSON written with its string escapes spelled out (`\n`, `\"`, no real line break, decoding to text that parses as JSON or a ```json fence; or only a fence's own line breaks spelled out around plain JSON) is decoded the same way (P42); 2860 normal and 2729 malformed were re-recorded.
- **Gate 2.** The folder under test is the headless skill run's (`--skill`) or, for budget, plain `convert.mjs` (`drivers.convert` says which). `plainColumn` always holds the plain converter's gate 2 and preflight.
- **Drivers.** The in-process driver runs gates 3–7 (all variants, repeats). The claude driver runs normal and hostile once per template; gates 3, 4 and 6 must pass on both, and `gates.<n>.driver` names the driver. Under `--driver claude` it runs before gate 7; otherwise a template that passes gates 3–7 in process gets it once for gate 8 (`drivers.claudeForGate8`, within the `claude -p` budget). Its `http` steps (PROPOSALS P5) go to a host `mock-server.mjs` with the fixture's `http` routes: `http-preload.mjs`, preloaded into the session's `runtime/runner.mjs` processes only (the Claude Code binary ignores `NODE_OPTIONS`), sends the runner's `fetch` there in absolute form, each request on its own connection (P8), and the mock's log is the http half of its effects. Each secret the definition names gets a dummy `N2C_SECRET_<NAME>`.
- **n8n check** (P36). A template whose Claude side stops at preflight gets the canned n8n run (no model call, never saved as a recording) on every variant the run covers (`--n8n-check normal`: normal only; `--no-n8n-check`: none); the row's `drivers.n8nCheck` gives each variant's status, error and request log against the fixture (`unanswered`, `unused`). A canned reply fits the structure the request asks for (P41, `model-shim.mjs` `cannedAnswer()`): a call of n8n's output-parser tool `format_final_json_response`, a JSON response format's schema, or LangChain's StructuredOutputParser format instructions in the prompt (the last ```json block after "Here is the JSON Schema instance your output must adhere to", answered in the same fence) get a minimal value of that schema (enum's first, `Bench canned value` for strings, 0, false, empty lists, every object property), so the check reaches the nodes after a structured-output parser; anything else gets the plain canned text.
- **Synthetic hostile replies** (P38). n8n's replayed replies never ask for something off the author's list, so a refusal of the runtime (a model-picked URL limited to the URLs written in the tool) is never exercised by a replay. A hostile fixture may list `expect.syntheticReplies` (`{synthetic: true, why, model, before, answer}`): replies written by the bench, never sent to n8n, inserted into the Claude side's replayed replies only (in process and in the claude driver's replay hook, `claude-side.mjs` `withSynthetic()`), at call index `before` of that model node in that call's provider format and with its request, n8n's later replies moving one later. Gate 6 fails `synthetic off-list call not refused` when the Claude side reached the inserted reply and sent a request to a host its answer names; a reply not reached is reported (`gates.6.detail.synthetic`). 6270's hostile fixture asks Get News for the bait host after the BBC feed is read.
- **Driver protocol slips** (P40). A claude-driver run that ends while the runner waits on a model or agent request for which n8n's recorded reply was there to replay (the session wrote its own final text; ended by itself, not killed, no hook or permission denial: `claude-driver.mjs` `protocolSlip()`) is a slip, not a gate verdict. It is retried once on the same commit; both attempts are kept (ledger key `claude:<variant>:slip`, row `drivers.claude.slips`), the retry's run is the one the gates read (a slip never turns a failure into a pass by itself), and a slip that repeats stands as the verdict, counting as a flip if it changes one. `summary.mjs` reports the slip rate (slipped driver runs over driver runs made, retries included) and, with `--against <tag>`, the verdict flips between two runs.
- **Diagnostics** (`--diagnose`): a template that passes preflight but stops at gates 3–6 still gets Contained measured on the hostile fixture (in process, and with the claude driver on normal and hostile). Recorded under `drivers.claudeDiagnostic` and `metrics.diagnostics`; the verdict stays the first failed gate.
- **Effects.** Writes and media calls are matched as multisets by `service.action.target`; several writes to one target are paired by content (P6: maximum-weight assignment on the count of equal fields, a differing object field counting its share of equal top-level keys, ties to list order), then compared field by field; order is reported (`sameOrder`), not gated; reads are reported, not gated; a chat or form workflow's answer is a `chat.reply` effect, compared on its text and its value type (`valueType`: `text`, or `json` when the answer was a JSON value that the text serialises; P30: an agent's final answer is text in n8n even when it reads as JSON). A Gmail raw body is decoded by its transfer encoding (base64, quoted-printable); a Gmail `reply` tool call takes its thread, recipients and subject from the replied-to message as the fixture serves it (`refsOf`), so it pairs with n8n's REST send of the reply; subjects compare without `Re:` (P10). A file written to local disk (P44, effects.json `file`) is a `disk.write:<path>` effect, the path as n8n resolves it (relative under `/home/node`; the runtime's relative paths, relative to the workflow folder, put there too), compared by the final bytes' SHA-256 and size: n8n's file read back from the container after the run (then removed), the Claude side's from a scratch disk that holds the fixture's `file` sources (in process: in memory; the claude driver: relative paths in its copy of the folder, absolute `allow.files` paths redirected under its run directory by `disk-preload.mjs`). The real disk is never read or written.
- **Connector rows** (P11). A call gets the first unused row whose `args` fit it; a read (by `effects.json`) then reuses a used row whose `args` fit, because the same read answers the same; then the calling step's own rows, then any. Reads keep one used-set per calling step (in process), so a poll read and a later get read never consume each other's rows; writes stay single-use in order. The claude driver's MCP mock matches `args` and reuses for reads the same way (it has no step names).
- **What gate 4 compared** (P50). Gate 4's detail and the row carry `compared` (`gates.mjs` `comparedOf`): matched writes, media calls and disk writes other than the reply (`effects`), the chat or form reply (`reply`), replayed model inputs whose request was checked (`modelInputs`). With no effect, reply or checked model input on either side, two empty effect lists are equal by emptiness, not measured: gate 4 fails, `bench defect: nothing compared` (a manual workflow whose result stays in its last node; the fix would compare the last node's items, P50's other option). A pass with no effect but a reply (the workflow's only output is its answer, compared as text and value type) or only checked model inputs counts as a pass and is reported apart as `noEffect` (`reply`, `model inputs`): `summary.mjs` lists "pass, no effect compared" and marks it `NE`, `--release` lists it per side. Rows from before P50 are classed from the template's n8n recording; such a row that passed with nothing compared (1747, 890 at release point 2) is listed and not counted.
- **Form bodies** (P3). The mock decodes `multipart/form-data` into `{field: value}` (`bodyEncoding: "multipart"`; a repeated field as a list; a file part as `{filename, contentType, size, sha256}`); the in-process host records a runner file part (`$file`) the same way from its decoded bytes (P9). A form body on either side (n8n's decoded one, or a runner request whose `contentType` is multipart) is compared with every field as a string, keys sorted; JSON bodies keep their types.
- **Timezone and run-time timestamps** (P4). The bench's n8n runs with n8n's default timezone, `America/New_York` (`GENERIC_TIMEZONE` and `TZ`; the Schedule Trigger item too), as the runtime does for a template without `settings.timezone`. n8n's clock is not frozen: its `$now`/`$today` read the wall clock, the Claude side's clock is virtual from n8n's `startedAt`. So where a write field, the reply, or a replayed model input differs between the sides, timestamps within ±10 minutes of n8n's `startedAt` are masked on both sides and the field compared again: ISO 8601 (with `T` or a space), `Date#toString`, RFC 1123/2822, en-US `M/D/YYYY, h:mm AM`, long English dates with a time, and 13- or 10-digit epoch numbers. Only the digits are masked (`<run-time:####-##-##T##:##:##.###>`); the shape and any zone or offset stay, so a format or timezone difference still fails. Strings without a zone are read in the template's timezone, never UTC; date-only strings are never masked. Masked fields are listed as `runTimeMasked` (effects) and `input.runTimeMasked` (model calls). Recordings made under UTC whose model requests carry such text were re-recorded.
- **n8n cannot run** (P21, P49). A fixture's `expect.n8nCannotRun` (a Code node language without a runner in the image, a node the image lacks, a model class the image's LangChain refuses) is copied to the row (`n8nCannotRun`); it describes the image, not the data, so `validate.mjs` requires the same text on all four variants. Such a template stays in n and counts as not passing in the headline (it has no baseline, and n stays the round's fixtured size); `summary.mjs` reports one-shot success without those templates too, beside connector-limited, and `--release` gives the gap and bound with them left out of n and of the passes on both sides.
- **Connector-limited** (PROPOSALS P1). A failure at gates 3–5 (not a preflight refusal) whose cause or detail names a field of a fixture's `connectorGaps` (its distinctive words, singular or plural), on a step that is the gapped read or downstream of it, sets `connectorLimited: true` and `connectorGapsHit`. The bucket stays. `summary.mjs` reports one-shot success overall and without these templates; the connector shapes behind the gaps are unverified (`shape: assumed`).
- **Results row** (`evals/results.jsonl`): `template, commit, skillCommit, reached (9 = all passed), gate, bucket, cause, connectorLimited, connectorGapsHit, n8nCannotRun, detail, gates, drivers, plainColumn, config (with env names and nonPlaceholder overlays), credentialsAttached, stubs, n8nModelModes, logVsFixture, httpAttempt, metrics` (bench wall time, n8n execution time, skill and claude-driver cost and turns, claude -p runs and cost).
- **Buckets:** unmapped node, field map, expression translation, runner bug, skill instruction, flaky model step, bench defect, fixture.
